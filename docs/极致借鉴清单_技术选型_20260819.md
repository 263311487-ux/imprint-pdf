# Imprint · 极致借鉴清单（技术选型 v1，2026-08-19）

> 目标：每一环节都借鉴社区最强的工具/实践，做到极致。写完代码前先对齐这份选型。

## 一、链路拆解（11 环节）

```
Markdown → [1解析] → 语义HTML → [3渲染] → PDF → [9质检] → 印刷级报告
                    ↓ [2结构化]            ↑ [8字体/嵌入]
                    [4中文排版]  [5设计系统]  [6代码高亮]  [7图表]  [10AI原生]  [11发布]
```

## 二、逐环节借鉴清单

### 1. Markdown 解析 → 选 markdown-it-py
- 社区：markdown-it-py 1,353★（100% CommonMark + 插件生态）、mistune 3,065★（快）、Python-Markdown 4,234★（老牌）、unified/mdast 5,021★（JS 语法树之王）
- 借鉴：**100% CommonMark 严格解析**（md-it-py）+ 扩展（表格/任务列表/脚注/围栏代码）
- 极致点：解析后输出**语义 HTML**（h1-h6/p/table/blockquote/code），这是 tagged PDF/无障碍的地基（PDF/UA 最佳实践：从语义源生成，不事后修复）

### 2. 结构化（frontmatter/目录/引用）
- 借鉴：YAML frontmatter（标题/作者/日期/主题色）+ 自动 TOC（id 锚点 + 页码链接，参考 md-preview-pdf 的 --toc）
- 极致点：frontmatter 里能直接配"主题 + 主色"，一行换肤

### 3. 渲染引擎 → 主 WeasyPrint，PrinceXML 作标杆对齐
- 社区：PrinceXML（商业之王，CSS Paged Media 支持最广，书级质量）、WeasyPrint 9,515★（免费，2026 对比评测：书/发票够用，@footnote 已支持）、paged.js 1,480★（浏览器 polyfill）、Chrome 原生 @page 增强中
- 借鉴：**以 PrinceXML 的特性清单为"满分标杆"**，WeasyPrint 为主引擎（免费/中文好/语义 HTML→tagged PDF），对不上的特性降级实现
- 极致点：`@page` 全部规格（size/margins/margin-boxes/counter(page)/:first/:left/:right）+ table header 跨页重复 + column-count + footnotes

### 4. 中文排版 → 严格按《中文排版需求》规范
- 权威规范：W3C《中文排版需求》（标点挤压 1/4 字宽、避头尾禁则）+ GB/T 图书出版规范（版心长宽比 1.4142:1 = A4 比例、正文宋体 10.5pt、首行缩进 2 字符、行距 1.5-2.0 倍）
- CSS 技术：`line-break: strict`（避头尾）、`text-spacing` 标点压缩、`hanging-punctuation`
- 字体：思源宋体 9,622★ / 思源黑体 17,097★（开源、子集嵌入）+ 苹方/霞鹜文楷 25,580★（可选气质字体）
- 极致点：**中英文混排间距（1/4 em）、西文 hyphenation、标点避头尾、竖排预留**——中文印刷级是竞品集体死亡点

### 5. 设计系统 → DTCG tokens + 主题即设计师作品
- 权威：W3C DTCG design tokens（2025.10 稳定版）、Style Dictionary 4（tokens→CSS）、Google DESIGN.md（2026-04，AI 可理解的设计 tokens）
- 借鉴：**每套主题 = 一个 tokens 文件**（colors/spacing/typography/radius/decoration）→ 程序生成 CSS → 换肤=换 tokens
- 排版经典（借鉴 effective-print-design）：Bringhurst《字体排印的元素》、Butterick《实用排印》、Tschichold——正文/标题比例 2:1.5:1、基线网格、寡行孤行控制
- 极致点：主题（modern 杂志/academic 书卷/minimal 极简/ink 线装）每套有完整色板+字体配对+装饰细节，tokens 同时输出给 AI 理解（DESIGN.md 思路）

### 6. 代码高亮 → Pygments + Shiki 配色
- 社区：Shiki 13,716★（最漂亮、JS）、highlight.js 24,981★、Pygments 2,201★（Python 原生）
- 借鉴：Pygments 生成带 class 的语义 HTML（WeasyPrint 友好）+ 借鉴 Shiki 的现代配色（github-dark/light 系）
- 极致点：代码块不跨页截断（break-inside: avoid）、行号、语言标签、等宽字体栈（JetBrains Mono/Consolas/等）

### 7. 图表 → Mermaid→SVG 矢量
- 社区：Mermaid 89,842★（文本→图）、ECharts 50k+★、plotly
- 借鉴：Mermaid 代码块 → 预渲染 SVG（mermaid-cli）→ WeasyPrint 嵌入矢量（印刷级清晰）；表格/流程图/时序图全支持
- 极致点：矢量图 + 图注 + 不溢出版心（max-width + 居中）

### 8. 字体与嵌入
- 社区：思源宋/黑体（开源嵌入）、qpdf 5,338★（PDF 工具）
- 借鉴：**子集嵌入**（文件小）+ `@font-face` + 字体栈回退（中文宋体→Heiti→PingFang→sans-serif）
- 极致点：中英数三字体正确配对、嵌入子集、PDF 元数据完整（标题/作者/语言标记）

### 9. PDF 质检 → 自研"印刷级评分器"（差异化核心）
- 社区：PyMuPDF 10,510★（提取/分析）、pdfplumber 10,679★（字符级）、qpdf 5,338★、veraPDF 339★（PDF/A）
- 借鉴：组合三件套——PyMuPDF（文本可选性/字体嵌入/元数据）、pdfplumber（避头尾违规检测：行首标点）、qpdf（结构完整性）
- 极致点：**0-100 印刷级评分**：文本可选/字体嵌入/避头尾违规数/孤行数/表格跨页/元数据/文件大小/审美一致性 + Poppler 渲染页面 PNG 视觉 QA（借鉴本机 pdf skill 的渲染验证流程）

### 10. AI 原生 → CLI + MCP server（2026 新空白）
- 社区：@docweave/mcp（generate_pdf 工具）、@formepdf/mcp（发票/收据/报告）、foliopdf-mcp（单二进制本地渲染，v0.2）、kedin-pdf——**全部是 2026 年 4-7 月刚出现、都还是 v0.x**
- 借鉴：CLI 一行命令 + MCP 工具（agent 一句"生成报告 PDF"直接出文件）+ 模板+JSON 模式（参考 carbone 2,093★：JSON→报告）
- 极致点：**LLM/Agent 输出 Markdown → 印刷级 PDF**，这是"AI 原生产物"时代缺的那一环

### 11. 发布/分发
- 借鉴：pip + npm 双发布 + GitHub 仓库 + 示例画廊（README 贴对比图：同一 Markdown，pandoc 默认 vs Imprint）+ skill 生态挂载（Claude Code / DSH）
- 极致点：`pip install imprint` / `npx imprint` 一条命令出成品，开箱即用零配置

## 六、社区深度探索补遗（2026-08-19 第二轮 · 写代码前最后对齐）

### 6.1 引擎全景结论（transformyio/html-to-pdf-libraries 权威对比）
- **print-grade 文档引擎排序**：PrinceXML（商业之王）> WeasyPrint（开源最佳，自己的 CSS 引擎，非浏览器）> Paged.js/Vivliostyle（浏览器 polyfill，⚠️ AGPL 传染）> Chromium 系（paged media 支持不完整，pandoc 至今默认 wkhtmltopdf/pagedjs 之争未落地）
- **WeasyPrint 能力实测通过**（本机 v69.0，Python 3.14）：见第 7 节
- **性能现实**：speedata 2026-02 基准，typst 500 页 157ms vs WeasyPrint 8.7s（慢约 55 倍）→ **不与 typst 正面刚速度**，差异化在中文印刷级 + 质检报告 + AI 原生 + 设计系统

### 6.2 AI 原生 PDF 竞品盘点（2026 新兴空白，全部 v0.x，无质检/无中文印刷级）
| 项目 | 形态 | 差异化缺口 |
|---|---|---|
| @druckform/mcp（2026-07） | Markdown→LaTeX→PDF，MCP 服务 | 无质检、无中文印刷级 |
| foliopdf-mcp（v0.2） | 单二进制本地渲染，render_markdown 工具 | 无质检报告 |
| mintpdf（2026-08） | HTML/Markdown→PDF，REST+MCP | 无设计系统 tokens |
| PiMd（2026-06，Python） | DOCX/EPUB/PDF-A/LaTeX，离线 | 非 AI 原生 |
| quarkdown（16k★） | MD→HTML/PDF，Puppeteer | paged media 受限 |
| Deckrun MCP / MDMagic-MCP / mcp-pandoc-omni | Markdown→PDF+音视频 | 工具链杂，无印刷级 |
- **洞见**：竞品全部缺「印刷级质检报告 + 中文规范排版 + DTCG tokens 主题」三件套 → 我们的三角差异化成立

### 6.3 Mermaid 纯 Python 渲染（v2 图表环节改选型）
- **mermaidx**（2026-07-30）：嵌入式 QuickJS + resvg，无 Node/browser 依赖，`render(src).svg()/png()/pdf()`
- **mmdc**：同引擎 CLI 包
- 选型更新：图表环节从「mermaid-cli（需 Node）」改为 **mermaidx（纯 Python）**，全栈零 Node 依赖，CI/CD 友好

### 6.4 设计系统可借鉴对象（tokens 直接参照）
- **Open Design · Publication design system**：印刷风设计系统，**56 tokens（palette/type/spacing/grid）专为 agent 可读**，DESIGN.md（散文约束）+ tokens.css（编译产物）+ 预览——正是我们「主题=tokens 文件 + 程序生成 CSS + AI 可读」的范本
- **AHD style token schema**：type system（families/scale/pairing/weights/tracking）+ OKLCH palette + grid 套件
- **typst 模板生态**（haobook、tufte-typst、kaobook 风）：作审美参照，尤其中文论文模板的版心/字体配对
- **CSS CJK 细节（tw93/Kami 设计规范）**：汉字密度需 `letter-spacing: 0.3pt` 级别微调；全文禁止 `text-transform: uppercase` 用于 CJK；中文句子必须全角标点

### 6.5 质检工具链（评分器可直接调用的现成工具）
- **veraPDF**：ISO 官方参考验证器，支持 PDF/A + PDF/UA + WTPDF，CLI 可入管道（Java，可选装）
- **pdfa11y**（speedata）：命令行 PDF 无障碍验证器，`--list-rules` 看规则集；不替代 veraPDF 正式验证
- **poppler-utils**：pdffonts/pdfinfo/pdftotext 已装，作评分器基础证据（字体嵌入/元数据/文本可选性）
- 加分项：WeasyPrint 66+ `pdf_variant='pdf/ua-1'` 输出 Tagged PDF（实测通过）→ PDF/UA 可作评分加分项

### 6.6 发布/增长策略（已有现成技能可借鉴）
- **渠道 ROI 排序**（github-optimization-skill 199-biotechnologies）：Stacked launch = HN + Reddit + X + Product Hunt 同日发射
- **Show HN 是首选发射渠道**：周二-四 9-11 EST，400-2500 upvotes 量级；30 分钟后 Reddit + X thread
- **README 前 50 行结构（DEV 实证 + AMiner 论文）**：一句话描述 + 截图/GIF + 安装 + <5 行快速开始；README 图片数、license、链接数与星数正相关
- **Agent skills 分发**：Claude/Anthropic skills 仓库、skills.sh API（2026-06 GA）、DSH 生态（dsh-skills）
- **awesome-list PR**：README-SVG repo-promotion-guide 有现成 checklist

### 6.7 排版实现细节（17golang/php.cn 实战排坑）
- 绝对单位（mm/pt）而非相对；避免 @media print 误用（WeasyPrint 本身就是 print 上下文）
- 表格防断页 `break-inside: avoid` + thead 自动重复（实测通过）
- 页眉页脚原生 @page margin-boxes 定义（实测通过），不要手画
- 字体回退：`fc-list` 确认 fontconfig 家庭名，CSS font-family 必须精确匹配（本机已确认 Songti SC/Heiti SC/Hiragino Sans GB）
- 西文连字：`hyphens: auto` 需配合元素 `lang` 属性 + pyphen 词典（实测中文页面内英文段落默认不触发，转换器需给西文块标注 lang="en"）

## 七、本机实测结论（2026-08-19 · weasyprint 69.0 真实跑通）

| 能力 | 结果 | 备注 |
|---|---|---|
| TOC 目录页码 `target-counter(attr(href), page)` + `leader(". ")` | ✅ 跨页精确（第2/3/4页） | 直接可用 |
| 表格跨页 `thead` 表头重复 | ✅ 跨页自动重复 | `display: table-header-group` |
| 页眉 running header `string-set` | ✅ 每章自动切换 | `@top-center` |
| 页码 `counter(page)` margin-box | ✅ | `@bottom-center` |
| 中文标点避头尾 | ✅ 检测 0 违规 | Pango 内置 kinsoku，无需 text-spacing |
| 字体子集嵌入 | ✅ CID TrueType 全子集 | pdffonts 确认 |
| PDF/UA Tagged | ✅ `pdf_variant='pdf/ua-1'` | pdfinfo Tagged: yes |
| 中文字体栈 | ✅ Songti SC/Heiti SC | fontconfig 家庭名直配 |
| 标点压缩 text-spacing 1/4em | ⚠️ 未证实 | 降级：西文四周 1/4em 间距用 CSS，中文标点靠 kinsoku 已够 |

**关键技术决策确认**：WeasyPrint 69 全链路能力足够 MVP（无需 Paged.js/Chromium）；`text-spacing` 不做硬依赖；西文块 lang 标注进转换器。
