# 第一章 为什么需要印刷级 PDF

在计算机诞生的头三十年里，"排版"是一门手艺，属于出版社与排版车间。铅字、字模、版心、避头尾、孤行寡行——这些词汇代表着一种近乎苛刻的审美纪律。到了数字时代，人人都能生成 PDF，但绝大多数工具生成的 PDF，只是"把文字倒进页面里"，距离"一本书"还有很远。

Imprint 的立场很朴素：Markdown 是内容的草稿，PDF 是内容的成品。既然要出成品，就应该按出版物的标准来排——正文宋体、标题黑体、首行缩进两个字符、标点不落在行首、目录页码精确可点、表格跨页自动重复表头、代码块不拦腰截断。这些不是炫技，而是读者打开文件第一眼就能感受到的"舒服"。

这份文档本身就是 Imprint 的产物。你正在阅读的每一页，都经过一套 0-100 分的印刷级质检：文本可选、字体子集嵌入、元数据完整、标点避头尾、孤行寡行、目录页码正确、PDF/UA 无障碍标签。分数写在命令行里，证据一目了然。

# 第二章 中文排版的六个细节

## 2.1 标点避头尾

中文排版有一条铁律：句号、逗号、顿号、分号、冒号、问号、感叹号、右括号、右引号，都不能出现在行首；左引号、左括号、左书名号，不能出现在行尾。这条规则来自《标点符号用法》和 W3C 的《中文排版需求》。在大多数浏览器里，这条规则并没有被严格执行，但印刷品必须做到。

我们把这条规则写进了质检器。每一页的每一行，程序都会检查行首字符是否违规。下面的段落故意写得足够长，让文字在标点附近换行——如果避头尾生效，你会看到任何一行都不会以"。"或"，"开头。按照中文排版规范，逗号、句号、分号、冒号、问号、感叹号等标点符号不能出现在行首；左引号、左书名号不能出现在行尾。这里把句子写得很长，就是为了让换行发生在标点附近，从而检验禁则是否真正生效，以及中文与西文混排时的字距是否自然协调。

## 2.2 中英文混排

中文字符与英文字符混排时，字与字之间应该保持视觉上的均匀。Imprint 的做法是：中文正文使用宋体，西文与数字使用同族西文字形，并在 CSS 层控制字距。英文段落自动开启连字（hyphenation），避免单词被生硬地截断。例如下面这段英文：

This is an English paragraph used to demonstrate automatic hyphenation in Imprint. The quick brown fox jumps over the lazy dog, and the typesetting engine carefully breaks long words such as internationalization and pneumonoultramicroscopicsilicovolcanoconiosis at natural syllable boundaries.

## 2.4 代码块不截断

代码块整体着色、整体换页，绝不会从中间被拦腰截断。语法高亮采用与 GitHub 一脉相承的暖色系，印在纸上依然层次分明。

```python
def hello(name: str) -> str:
    """Return a greeting. 中文注释混排测试。"""
    message = f"Hello, {name}! 你好，世界。"
    return message


for i in range(10):
    print(hello(f"user_{i}"))
```

# 第三章 从 Markdown 到一本书

## 3.1 一行命令

```bash
imprint sample.md -o sample.pdf
```

`imprint` 会读取 Markdown 开头的 YAML 元信息（标题、作者、日期、主题），生成封面页与目录，渲染正文，最后跑一遍质检并打印分数。

## 3.2 主题即设计系统

每套主题都是一组设计令牌（design tokens）：色板、字体配对、间距、装饰细节。换主题只需改一行：

```bash
imprint sample.md --theme academic
```
